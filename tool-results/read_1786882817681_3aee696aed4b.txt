    13→    13→### 1. ROON — The Audiophile Gold Standard
    14→    14→
    15→    15→**Price**: $12.99/mo (lifetime $899) | **Architecture**: Core + Remote + RAAT protocol + ARC (mobile)
    16→    16→
    17→    17→#### Key Differentiating Features
    18→    18→
    19→    19→| Feature | Details |
    20→    20→|---------|---------|
    21→    21→| **Metadata Engine** | Proprietary enriched dataset sourced from MusicBrainz, TiVo/AllMusic, Rovi. Cross-references performers, composers, producers, engineers. Every person is a link to deep biographical info. |
    22→    22→| **Classical Music** | Composer-first hierarchy (not artist-album-track). Supports multi-part works (movements), period, instrumentation, form. Lists conductor, ensemble, soloists, recording venue, and date per recording. |
    23→    23→| **Versions** | Shows all album versions (different masterings, sample rates, encodings) across local + streaming (Qobuz, TIDAL, nugs, KKBOX). User can highlight a favorite version. |
    24→    24→| **MUSE DSP Engine** | Parametric + procedural EQ, volume leveling, upsampling, room correction (convolution), headphone crossfeed. Works on PCM, MQA, DSD. Up to 768kHz/32-bit PCM and DSD512. |
    25→    25→| **Signal Path Display** | Transparent real-time view of every processing step between source file and DAC output. Shows sample rate, bit depth, bit-perfect status per stage. |
    26→    26→| **Multi-Room Sync** | Synchronized playback to multiple endpoints via RAAT protocol. Zone grouping with sample-accurate sync. |
    27→    27→| **Discovery** | Infinite cross-linking: influences, followers, collaborators, related artists — even for artists NOT in your library. |
    28→    28→| **Lyrics** | Synced (line-by-line scrolling) and static lyric sheets for millions of tracks. |
    29→    29→| **Localization** | "Fluency" — UI genres, credit roles, artist name transliteration to other character sets. Wikipedia reviews in 20 languages. |
    30→    30→| **Bit-Perfect** | Checks DAC capabilities, adjusts sample rate/bit depth automatically. ASIO/WASAPI/CoreAudio exclusive mode. |
    31→    31→
    32→    32→#### What Roon Does BETTER Than Anyone
    33→    33→- **Metadata density**: No other platform comes close to linking composers → performers → recording venues → works → movements.
    34→    34→- **Unified library**: Seamlessly merges local files + 4 streaming services into one browsable, cross-referenced graph.
    35→    35→- **Classical music**: The only platform that treats classical music as first-class with proper work/movement hierarchy.
    36→    36→- **Signal Path transparency**: The gold standard for showing exactly what's happening to the audio.
    37→    37→
    38→    38→#### UX Patterns Worth Copying
    39→    39→1. **Everything is a link** — tap any person, place, or credit to explore deeper.
    40→    40→2. **Version comparison** — see all masterings of an album side-by-side with quality indicators.
    41→    41→3. **Focus/focus+ layouts** — clean, visual browsing that scales from album art grids to dense metadata tables.
    42→    42→4. **Valence** (AI-powered recommendations launched 2024) — uses listening habits + metadata graph for discovery.

   271→   271→## PART 3: GAP ANALYSIS — Prioritized by Impact
   272→   272→
   273→   273→### TIER 1: Critical Gaps (High Impact, Feasible in Web Audio)
   274→   274→
   275→   275→#### GAP-1: Audio Visualization (AnalyserNode)
   276→   276→**Who does it best**: Plexamp
   277→   277→**Current State**: DSP has zero visualization. No `AnalyserNode` is created in `audio-engine.ts`.
   278→   278→**Why Critical**: Visual feedback is the single most impactful UX differentiator for a web-based player. It's what makes the app feel *alive*.
   279→   279→
   280→   280→**Implementation (Web Audio API)**:
   281→   281→```
   282→   282→Add AnalyserNode branch from the DSP chain → Canvas/WebGL renderers
   283→   283→```
   284→   284→- Add `AnalyserNode` to the DSP chain (before master gain)
   285→   285→- Create 3 visualization modes:
   286→   286→  - **Spectrum bars** — frequency domain (`getByteFrequencyData`)
   287→   287→  - **Waveform** — time domain (`getByteTimeDomainData`) 
   288→   288→  - **Circular visualizer** — frequency mapped to radial bars (Plexamp Glow-style)
   289→   289→- Use `requestAnimationFrame` loop with Canvas API (no WebGL needed for initial impl)
   290→   290→- Expose visualization data to React via a custom hook (`useAudioAnalyser`)
   291→   291→- ~3-4 days effort
   292→   292→
   293→   293→---
   294→   294→
   295→   295→#### GAP-2: Real-Time Loudness Measurement (EBU R128 / ReplayGain)
   296→   296→**Who does it best**: Roon (MUSE engine), Audirvana
   297→   297→**Current State**: DSP has `LoudnessConfig` with `targetLUFS` and method fields, but the audio engine just applies a static `fallbackGain` (1.0). No actual LUFS measurement.
   298→   298→**Why Critical**: The loudness normalization feature is currently non-functional. This is a core audiophile feature.
   299→   299→
   300→   300→**Implementation (Web Audio API)**:
   301→   301→```
   302→   302→OfflineAudioContext → RMS measurement → LUFS calculation → gain compensation
   303→   303→```
   304→   304→- Implement EBU R128 short-term loudness measurement using `OfflineAudioContext`
   305→   305→- Pre-scan tracks on load to measure integrated loudness
   306→   306→- Cache LUFS values per track in IndexedDB / server-side DB
   307→   307→- Apply real-time gain compensation in the loudness GainNode
   308→   308→- Show measured LUFS value in Now Playing and Signal Path views
   309→   309→- ~5-7 days effort
   310→   310→
   311→   311→---
   312→   312→
   313→   313→#### GAP-3: Gapless Playback
   314→   314→**Who does it best**: Roon, Apple Music, every serious player
   315→   315→**Current State**: Store has `gaplessPlayback: boolean` flag. No implementation. Web Audio `HTMLAudioElement` doesn't natively support gapless.
   316→   316→**Why Critical**: Audible gaps between tracks (especially in classical/concept albums) break the listening experience. This is table-stakes.
   317→   317→
   318→   318→**Implementation (Web Audio API)**:
   319→   319→```
   320→   320→Web Audio API → AudioBufferSourceNode scheduling with precise timing
   321→   321→```
   322→   322→- Switch from `HTMLAudioElement` to `AudioBufferSourceNode` for local files
   323→   323→- Use `AudioContext.currentTime` for sample-accurate scheduling
   324→   324→- Pre-decode next track while current plays
   325→   325→- Crossfade overlap (0-500ms configurable)
   326→   326→- For streaming URLs, use MediaSource Extensions (MSE) or keep HTMLAudioElement with timed pre-loading
   327→   327→- ~5-7 days effort
   328→   328→
   329→   329→---
   330→   330→
   331→   331→#### GAP-4: Lyrics Display (Synced + Static)
   332→   332→**Who does it best**: Apple Music (Sing), Spotify, Roon
   333→   333→**Current State**: Track type has `lyrics?: string` field. `useLyrics` hook exists in `NowPlayingView.tsx` but implementation is unclear/external. No lyrics display component.
   334→   334→**Why Critical**: Lyrics are the #1 most-requested feature in any music app. It's expected behavior.
   335→   335→
   336→   336→**Implementation**:
   337→   337→```
   338→   338→LRCLIB.net API (free) → sync lyric parsing → scroll-along component
   339→   339→```
   340→   340→- Integrate LRCLIB.net or Musixmatch API for lyrics fetching
   341→   341→- Parse LRC format (timestamped lyrics) for synced display
   342→   342→- Create `LyricsView` component with:
   343→   343→  - Auto-scroll to current line (smooth CSS transform)
   344→   344→  - Tap-to-seek on lyric lines
   345→   345→  - Static/synced toggle
   346→   346→- Cache lyrics server-side in DB
   347→   347→- ~3-4 days effort
   348→   348→
   349→   349→---
   350→   350→
   351→   351→### TIER 2: High-Impact Gaps (Strong Differentiation)
   352→   352→
   353→   353→#### GAP-5: Smart Discovery / Recommendation Engine
   354→   354→**Who does it best**: Spotify (AI DJ, Daylist, Discover Weekly)
   355→   355→**Current State**: `discovery.ts` store has `startRadioFrom()` that returns an empty radio with no tracks. No collaborative filtering, no audio analysis.
